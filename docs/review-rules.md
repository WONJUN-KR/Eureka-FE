# 리뷰 규칙

PR 리뷰(Claude /code-review · 코드래빗 · unslop)에서 반복해서 나온 지적을 규칙으로 모은 문서. 코드를 쓰기 전에 읽고, PR 올리기 전에 아래 체크리스트로 한 번 더 본다. 새로 나온 지적 중 다시 나올 만한 것은 여기에 덧붙인다.

## 화면 상태

### 1. API 실패와 빠진 응답 필드는 빈 화면과 구분한다

- 요청이 실패하면 '아직 글이 없어요' 같은 빈 상태 문구를 보이지 않는다. `isError` 를 따로 보고 오류 문구와 '다시 불러오기' 버튼을 둔다.
- 응답 필드가 빠지거나 null 일 수 있으면 `src/api/types.ts` 에서 선택값(`?:` · `| null`)으로 적고, 쓰는 곳에서 기본값(`?? []`)을 둔다.
- 화면을 띄우는 데 필요한 조회(내 정보 · 사진 목록 등)가 실패해도 빈 화면(`return null`)으로 끝내지 않는다.
- 나온 곳: #13 · #17 · #20 · #22

### 2. 로딩 대체 화면과 실제 화면의 높이를 맞추고, 사용자 입력은 넘치지 않게 한다

- Suspense · 로딩 대체 화면은 실제 화면의 제목 · 필터 · 칩 줄 · 검색칸 · 사진 칸과 같은 높이를 잡는다. 내용이 들어올 때 아래가 밀리면 안 된다(CLS).
- 빈 줄을 잡을 땐 `' '` 대신 줄바꿈 없는 공백(`' '`)을 쓴다. 일반 공백은 줄 높이를 못 잡는다.
- 사용자 입력이 그대로 나오는 제목 · 이름은 `[overflow-wrap:anywhere]` 와 부모 `min-w-0` 으로 휴대폰에서 넘치지 않게 한다.
- 나온 곳: #12 · #14 · #20 · #23

### 3. 첫 렌더가 서버 HTML 과 같게 한다 (hydration)

- 다른 컴포넌트가 같은 쿼리를 먼저 받아오면 Suspense 안 화면의 첫 렌더가 서버 HTML 과 달라질 수 있다. 캐시 데이터로 그리는 화면은 마운트 전엔 대체 화면을 그린다(`useSyncExternalStore` 로 마운트 확인, `src/app/posts/page.tsx` 참고).
- 로그인 상태처럼 브라우저 저장소에서 읽는 값은 `isHydrated` 전엔 자리만 잡고 보이지 않게 한다.
- 나온 곳: #12 · #14

## 입력 · 접근성

### 4. 제출 중에는 입력과 닫기를 막는다

- 글 저장은 버튼으로만 한다. 여러 칸이 있는 편집 화면을 `<form>` 으로 감싸면 아무 칸에서나 Enter 로 저장된다.
- 저장 · 신고를 보내는 동안엔 입력 칸과 취소 버튼을 잠근다(`<fieldset disabled>`). 창(모달)은 보내는 동안 Esc · 바깥 클릭 · 취소로 닫히지 않게 한다.
- 결과 처리(성공 안내 · 상태 바꾸기)는 `mutate` 호출 쪽이 아니라 `useMutation` 옵션에 둔다. 호출 쪽 콜백은 화면이 닫히면 실행되지 않는다.
- 나온 곳: #21 · #22 · #26

### 5. 창 · 고를 수 있는 요소는 키보드로 쓸 수 있게 한다

- 창(사진 뷰어 · 신고 창)은 `src/hooks/useDialogFocus.ts` 를 쓴다: 열면 안으로 포커스, Tab 은 창 안에서만, 닫으면 연 요소로.
- 연 요소가 잠기거나 사라지면(신고 후 '신고함') 포커스를 안내 문구 등 다른 요소로 옮긴다.
- 화면 안에서 위치를 옮기는 동작(장소로 스크롤)은 키보드 포커스도 같이 옮긴다.
- 클릭으로 고르는 요소(약도 핀 등)는 `role="button"` · `tabIndex={0}` · Enter/Space 를 둔다. 고를 수 있는 요소를 `role="img"` 안에 두지 않는다.
- 탭처럼 보이는 버튼에 `role="tab"` 을 쓰려면 화살표 키 · `aria-controls` 까지 갖춘다. 아니면 `aria-pressed` 버튼으로 둔다.
- 글자 대비는 4.5:1 이상. 주황(`trail`)은 지도 경로 · 누른 좋아요에만 쓴다.
- 나온 곳: #12 · #13 · #19 · #20 · #23 · #24 · #26

## 주소 · 데이터

### 6. 화면 상태는 주소(URL)에 두고, 주소는 Next 라우터와 같이 바꾼다

- 필터는 짝으로 넘긴다: `regionId` + `cityId`, `categoryId` + `subCategoryId`. 목록 화면은 일부만 와도(`?cityId=` 만 등) 제목 · 선택 상태를 보여준다.
- 새로고침 · 뒤로 가기 뒤에도 남아야 하는 상태(마이페이지 탭 등)는 주소(`?tab=likes`)에 둔다.
- `window.history.replaceState` 를 쓸 땐 state 를 `null` 로 넘긴다. `window.history.state` 를 그대로 넘기면 Next 가 내부 호출로 보고 라우터 주소(`useSearchParams`) 동기화를 건너뛴다.
- 나온 곳: #14 · #20 · #24

### 7. 데이터를 바꾸면 관련 캐시를 같이 다시 받고, 목록은 이어 받는다

- 글 쓰기 · 수정 · 삭제 · 좋아요 · 신고 뒤 무효화할 쿼리 키를 `src/api/queryKeys.ts` 기준으로 빠짐없이 적는다(글 목록 · 상세 · 사람별 글 · 프로필 · 추천한 글).
- 로그아웃하면 사용자 캐시(`queryKeys.user.all`)를 지운다(`src/app/providers.tsx`).
- 개수가 늘어나는 목록은 한 번에 다 받지 않고 `useInfiniteQuery` 로 이어 받는다('더 보기').
- 정렬 파라미터를 보낼 땐 동점끼리 순서가 정해지도록 `id,desc` 를 뒤에 붙인다. 안 붙이면 페이지끼리 같은 글이 겹친다.
- 나온 곳: #14 · #17 · #24 · #26

## 외부 연동 · 인증

### 8. 외부 SDK 는 시간 제한과 실패 화면을 둔다

- 카카오 지도 SDK 처럼 스크립트를 불러오는 것은 시간 제한(8초)을 두고, 실패하면 대체 화면(약도)으로 넘어간다.
- 다시 시도할 수 있는 로딩은 시도 번호로 구분해, 늦게 끝난 예전 시도가 지금 시도의 상태를 지우지 않게 한다(`src/lib/kakao.ts`).
- 나온 곳: #19

### 9. 로그인 결과는 주소에 토큰을 싣지 않고, 시작한 브라우저에서만 받는다

- 외부 로그인(카카오)은 시작할 때 nonce 를 만들어 localStorage 에 두고 BE 에 넘긴다. 콜백에선 주소의 1회용 code 를 그 nonce 와 함께 교환한다(`src/lib/kakaoLogin.ts`).
- 교환 요청은 한 번만 보낸다(개발 모드 effect 두 번 실행 가드). nonce 는 꺼낼 때 바로 지운다.
- 이미 로그인된 채로 콜백에 다시 오면(뒤로 가기) 실패 안내 대신 홈으로 보낸다.
- 나온 곳: #25

## 코드

### 10. 있는 공용 코드를 다시 구현하지 않는다

- 버튼 · 입력 모양은 `src/components/ui/field.tsx` 의 `buttonClass` · `inputClass` 를 쓴다.
- 같은 동작이 두 번 나오면 함수 하나로 묶는다(목록 이동 `goList`, 장소로 이동 `focusStop`, 창 포커스 `useDialogFocus`).
- 나온 곳: #12 · #20 · #23 · #26
